# P-Core Orchestra — orchestra notes

## Repo type: single-repo

This is a **single repository** (not a monorepo). All source lives under `bundle/`, `scripts/`, `docs/`, `templates/`. Scope all reads and globs to this repo root only — do not scan sibling directories under `pcore/`.

## Performance scoping rules

- **Never glob `**/` from a parent directory** — it triggers scans of thousands of files across sibling projects.
- Use project-relative paths: `AGENTS.md`, `context/*.md`, `bundle/**/*.js` — not `**/AGENTS.md`.
- This repo has `.ignore`, `.cursorignore`, and `.gitignore` that exclude `node_modules/`, `templates/**/node_modules/`, and skill bundle copies. Respect them.
- When searching, use `rg` (respects `.ignore`) — not bare `find` or `grep -r`.
- Read only the files you need for the current task; do not dump-read directories.

## Application building context

Read the following files in order before implementing or making architectural decisions:

0. `context/harness-scaffold-loop.md` — agent architecture hierarchy (harness, scaffold, loop)
1. `context/project-overview.md` — product definition, goals, features, scope
2. `context/architecture.md` — system structure, boundaries, storage, system design & infrastructure, invariants
3. `context/code-standards.md` — Node hook scripts, agent markdown, install conventions
4. `context/ui-context.md` — N/A for this repo (CLI/hooks only); skip unless editing docs site
5. `context/ai-workflow-rules.md` — scoping, doc sync, verification, six-file integration
6. `context/progress-tracker.md` — current phase, completed work, next steps

Update `context/progress-tracker.md` after each meaningful implementation change. If architecture or scope changes, update the relevant context file before continuing.

## Commands

```bash
# Install orchestra globally (Cursor + OpenCode + Qoder)
# Merges Cursor CLI/permissions/sandbox + OpenCode autonomy (MCP preserved) + Qoder settings.json hooks
bash install.sh
bash install.sh --all        # all three (default)
bash install.sh --cursor     # Cursor only
bash install.sh --opencode   # OpenCode only
bash install.sh --qoder      # Qoder CLI only
bash install.sh --project    # + project bridge in cwd

# Pin cheap Cursor model default (Composer 2.5 standard)
bash scripts/setup-cursor-model.sh

# Validate OpenCode free models (config + all agent frontmatter)
bash scripts/update-free-models.sh --check
bash scripts/update-free-models.sh --refresh  # refetch list first
bash scripts/update-free-models.sh --refresh --apply  # dynamic primary+heavy from live pools
bash scripts/update-free-models.sh --pools    # print frontend/heavy/light pools
bash scripts/update-free-models.sh --schedule # weekly timer (systemd; cron fallback)

# Autonomy merge only (no full bundle copy)

# Bootstrap six-file context in a project (orchestra-aware)
bash scripts/init-context.sh /path/to/your-project
bash scripts/init-context.sh /path/to/your-project --bridge

# Health / control (Cursor)
```

## Six-file context + orchestra

Projects with a `context/` folder (six files) get automatic context injection at session start and when orchestra activates. The planner reads all six files before planning; implementer follows `code-standards.md` and `architecture.md` invariants; verifier checks against spec/progress-tracker; reviewer confirms doc sync per `ai-workflow-rules.md`.

Bootstrap templates: `bash scripts/init-context.sh <project-dir>`

## OpenCode integration

OpenCode uses a skill- and plugin-driven approach instead of a hooks config:

- **Ambient plugin** `bundle/opencode/plugins/orchestra-ambient.js` (default export `{ id, setup }`) appends the orchestra policy to each session's system prompt so any agent runs the loop; a plugin failure can never break session start

- **Config is native V2** (`agents`, `permissions[]`, `providers`, `snapshots`,
  `mcp.servers`, `compaction.buffer`) — `bundle/config/opencode/autonomy.json`
  ships V2; `scripts/lib/opencode-v2.js` migrates any legacy V1 config in
  place during install/merge (behavior-preserving; oracle-tested via
  `opencode debug config` in `scripts/test-opencode-v2.js`)
- **Agents** are defined as markdown files in `~/.config/opencode/agents/`
- **Conductor** `orchestra.md` is `default_agent`; phase agents are `hidden: true`
- **Spawn:** OpenCode **`subagent`** tool (V1 name: `task`) + agent name (not
  Cursor **`Task`** + `subagent_type`)
- **Skills** at `~/.config/opencode/skills/` — orchestra-loop + UI skills + Cloudflare
- **State** at `~/.config/opencode/hooks/state/orchestra.json`
- **External discovery** via symlinks under `~/.agents/skills/` (orchestra-loop, prompt-intake, verification-before-completion, ui-ux-pro-max, brand, design-system, ui-styling, web-design-master)

Cross-platform spawn matrix: `docs/orchestra-cross-platform.md`

The OpenCode agents mirror the Cursor agents but use OpenCode's frontmatter format (`mode: subagent` instead of `readonly: true`).

## Qoder CLI integration

Qoder reuses the Cursor hook scripts with a settings.json event surface:

- **Agents** at `~/.qoder/agents/` — converted frontmatter (`disallowedTools`, `maxTurns`, `permissionMode`, `effort`) generated by `scripts/sync-qoder-agents.js` from `bundle/agents/` into `bundle/qoder/agents/`; run `--check` in CI to catch drift
- **Spawn:** Qoder **`Agent`** tool + `subagent_type` (same parameter name as Cursor's `Task`)
- **Hooks** registered in `~/.qoder/settings.json` under PascalCase events (`SessionStart`, `UserPromptSubmit`, `SubagentStop`, `Stop`) by `scripts/merge-qoder-settings.js` (idempotent, backs up, preserves model/security/mcpServers)
- **Hook input shim:** Qoder stdin carries `agent_type`; `bundle/hooks/lib/io.js` `normalizeHookInput()` maps it to `subagent_type` so the shared hooks work unchanged
- **Skills** at `~/.qoder/skills/{name}/SKILL.md` — same layout as Cursor, copied as-is
- **State** at `~/.qoder/hooks/state/orchestra.json` (or `PCORE_STATE_DIR`)

Cross-platform spawn matrix: `docs/orchestra-cross-platform.md`
